In order to assess Neo4j in a structured and theoretically grounded manner, this report adopts the framework developed by Brown and Wallnau \cite{brown:96} for evaluating software technology. Their approach was introduced to bring greater rigor and repeatability to technology assessments, emphasizing both qualitative and quantitative evaluation methods. The framework focuses on identifying the technology delta—that is, the distinct features that differentiate a technology from its peers—and systematically evaluating how these features contribute value within specific usage contexts.

As shown in Figure~\ref{fig:framework}, the framework is divided into three main phases: descriptive modeling, experiment design, and experiment evaluation. Together, these phases provide a comprehensive structure for analyzing how Neo4j’s key concepts, architecture, and performance compare to alternative cache technologies.

\subsection{Descriptive Modeling}

write where the technology comes from, its history, its context and what problem it solves.
Consider drawing a graph like in \cite{brown:96}.
\\
\\
Neo4j originates from 2000 when Emil Eifrem and his team at Neo Technology began developing a database solution to handle complex, interconnected data more efficiently than traditional relational databases could. The first version of Neo4j was released in 2007 as an open-source graph database. It quickly gained traction where developers and enterprises needed flexible data models. Neo4j is now one of the most widely used graph databases.

relational databases (SQL) are efficient for structured data, Neo4j was created as an answer to the problem where relational databases would struggle with highly connected data. 

So in the late 2000s Neo4j emerged with the NoSQL movemevent where organizations needed more flexible scalable and schema free databases. Other NoSQL types are key-value stores, document stores and column family stores all solving specific problems, graph databases like Neo4j targets relationship-heavy data.

The problem Neo4j solve is where relationships are as important as the data itself. This is ideal for social networks which we could eventually want to use, or recommendation systems where we were thinking you could recommend relevant polls to users.

The key feature delta that distinguishes Neo4j from both relational and other NoSQL databases lies in its native graph storage model and relationship-centric query language (Cypher). Instead of relying on costly table joins, Neo4j uses index-free adjacency, meaning each node directly stores references to connected nodes, enabling constant-time traversal across relationships. This makes it highly efficient for queries that explore deep or complex data networks.
According to \cite{guia2017neo4j}, Neo4j introduces several defining features that reinforce this delta: it has its own Cypher query language, designed specifically for graph manipulation; it employs a disk-based proprietary storage system optimized for graph persistence; it guarantees ACID transaction integrity—a rare trait among NoSQL systems; and it provides an intuitive, accessible user interface that simplifies visualization and query management.
Together, these characteristics highlight Neo4j’s unique combination of graph-native efficiency, strong consistency guarantees, and user-friendly design, which collectively form its technological delta compared to both relational and non-relational peers.
